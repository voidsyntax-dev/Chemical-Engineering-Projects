# Day-ahead solar and wind forecasting for Belgium

Leak-free **1–24 h ahead** forecasts of Belgian national **solar PV**, **onshore wind** and
**offshore wind** generation, built with LightGBM on archived ECMWF weather forecasts, with
**10 / 50 / 90 % prediction intervals**.

The point of the project is honest evaluation: every model input is something that was really
available at the moment the forecast was issued. Weather inputs are the NWP forecasts that had
actually been published by then, not the weather that later happened. See
**[LEAKAGE.md](LEAKAGE.md)** for the full argument.

## At a glance

| | Solar (daytime) | Onshore wind | Offshore wind |
|---|---|---|---|
| **LightGBM nRMSE** (% of capacity) | **5.81** | **3.94** | **8.57** |
| Skill vs. strongest simple baseline | +54 % | +10 % | +23 % |
| Elia's own day-ahead forecast (yardstick) | 5.05 | 4.08 | 8.85 |

Test period: forecasts issued 1 Mar – 31 May 2025, never used for any modelling choice.

## Quick start

Requires Python 3.12 (other 3.10+ versions will likely work).

```powershell
py -3.12 -m venv .venv
```
```powershell
.venv\Scripts\python.exe -m pip install -r requirements.txt
```
```powershell
.venv\Scripts\python.exe train.py
```

On macOS / Linux: `python3 -m venv .venv && .venv/bin/pip install -r requirements.txt && .venv/bin/python train.py`.

`train.py` runs in under a minute on a laptop CPU. It fits 12 models, writes them to `models/`
(overwriting any existing ones) and prints the test-period scores shown below.

## Data

| What | Source | Notes |
|---|---|---|
| Solar PV, onshore and offshore wind generation + monitored capacity | [Elia open data](https://opendata.elia.be/) (`ods032`, `ods031`) | 15 min, averaged to hourly |
| Weather inputs: archived ECMWF IFS 9 km runs (00 and 12 UTC) | [Open-Meteo Single Runs API](https://openmeteo.substack.com/p/single-runs-api) | 7 points over Belgium |
| Reference only: ERA5 reanalysis | [Open-Meteo Historical Weather API](https://open-meteo.com/en/docs/historical-weather-api) | not in the datasets |

Period covered: forecasts issued **14 Mar 2024 → 31 May 2025** (archived forecasts start on
14 Mar 2024). All timestamps are UTC. Details in [DATA_SOURCES.md](DATA_SOURCES.md).

### Dataset schema

**One row = one forecast**, keyed by `issue_time` (07:00 or 19:00 UTC), `lead` (1–24 h) and
`target_time`.

| Column group | Meaning |
|---|---|
| `<tech>_y` | **Target**: generation ÷ capacity known at issue time (capacity factor) |
| `<tech>_mw`, `<tech>_cap_issue`, `<tech>_cap_target` | Actual MW and capacities, for converting and scoring |
| `solar_ghi`, `solar_dir`, `solar_dif`, `solar_cloud`, `solar_kt_fc`, … | Forecast irradiance, cloud cover, clear-sky index (capacity-weighted over provinces) |
| `zenith`, `ghi_clear`, `is_day` | Sun position and clear-sky irradiance (pvlib) |
| `<wind>_ws100`, `_ws100_cubed`, `_rho`, `_wpd`, `_shear`, `_wd_sin/cos` | Forecast 100 m wind, air density, wind power density, shear, direction |
| `<tech>_cf_last`, `_cf_last3`, `_cf_samehour` | Lagged generation, all observed ≥ 1 h before issue time |
| `<tech>_elia_da` (+ `_p10` / `_p90`) | Elia's own day-ahead forecast (external yardstick) |
| `offshore_curtailed`, `offshore_gap` | Hours excluded from offshore training and scoring |

`<tech>` ∈ {`solar`, `onshore`, `offshore`}; `<wind>` ∈ {`onshore`, `offshore`}.

## Method

- **Timing.** Forecasts are issued at 07:00 and 19:00 UTC, 7 h after the 00/12 UTC ECMWF runs,
  roughly when those runs become available in real time. Lead *L* uses forecast step 7 + *L*.
- **Split.** Test = forecasts *issued* from 1 Mar 2025. Train = only targets that had been observed
  by then. The number of boosting rounds is chosen on the last 60 days of training data with the
  same rule. No random splitting.
- **Models.** Per technology: one LightGBM point model (lead time is a feature) and three quantile
  models (10 / 50 / 90 %). Quantiles are sorted per row so they never cross; solar is forced to 0
  at night. Hyperparameters are fixed in `train.py`, not tuned.
- **Baselines.**
  - Same-hour persistence (all technologies)
  - Last-value persistence (wind)
  - Clear-sky-scaled persistence (solar)
  - Isotonic power curve on forecast 100 m wind speed alone (wind)
- **Scoring.** nMAE and nRMSE in % of capacity at target time; skill = 1 − nRMSE / nRMSE of the
  reference. **Solar is scored on daytime hours only.** Offshore excludes curtailed hours and the
  window when Elia's data miss one wind farm. All models are scored on the same hours.

## Results (test: Mar–May 2025)

nRMSE in % of capacity. Skill reference: clear-sky persistence for solar, the power curve for wind.

| Model | Solar (daytime) | Onshore wind | Offshore wind |
|---|---|---|---|
| Persistence (same hour yesterday) | 12.55 | 12.80 | 26.08 |
| Persistence (last value) | – | 11.12 | 21.23 |
| Clear-sky persistence | 12.60 | – | – |
| Power curve (forecast wind speed only) | – | 4.39 | 11.11 |
| **LightGBM** | **5.81** (skill +54 %) | **3.94** (+10 %) | **8.57** (+23 %) |
| *Elia's own day-ahead forecast\** | *5.05* | *4.08* | *8.85* |
| Scored hours | 2,526 | 4,300 | 1,324 |

\* Elia's forecast is published the day before at 11:00 Brussels time (not matched to our issue
times), uses far more inputs, and Elia also produces the solar "measured" values. It is a
yardstick, not a like-for-like comparison.

**Prediction intervals.** The 10–90 % intervals contain 74 % (solar), 74 % (onshore) and 72 %
(offshore) of actual values against an 80 % target, so they are too narrow.

**Takeaways**

- **Forecast weather does most of the work.** A power curve on forecast wind speed alone beats
  persistence by 57–66 %; LightGBM improves on it by a further 10–23 %.
- **Solar gains most over its baseline** (+54 %), because persistence can't anticipate cloudy days.
- **Leakage would have flattered the results.** An earlier evaluation (code since removed) trained
  the same model on ERA5 "perfect" weather: wind errors were 11–14 % lower, which is how much a
  reanalysis-trained model would overstate its accuracy. The same evaluation showed conformal
  recalibration lifts interval coverage to 83–86 %. Neither result is reproducible from this repo.

## Limitations

- **Short test period.** One spring. Offshore has only ~1,300 scored hours (mostly March 2025),
  because Elia's offshore series is missing a wind farm from April to September 2025.
- **Short history.** One year of training data (Mar 2024 – Feb 2025); the forecast download stopped
  at July 2025.
- **Intervals are too narrow** (72–74 % vs 80 %), and the solar median is biased high in spring
  (69 % of actuals fall below it). `train.py` does not recalibrate the intervals.
- **The target is partly an estimate.** Elia's solar and DSO-connected wind "measurements" are
  upscaled from metered samples.
- **Coarse inputs.** Seven grid points for all of Belgium, one weather model (ECMWF IFS), no ensemble.
- **Timing assumptions.** NWP runs are assumed usable 7 h after initialisation, and generation 1 h
  after measurement.
- **Daytime definition.** Solar is scored whenever the sun is above the horizon, including near-zero
  dawn/dusk hours, which slightly lowers the average error.
- **Not reproducible end to end.** The data-building code was removed; the datasets must be taken
  as given.
- **Unpinned dependencies.** `requirements.txt` has no version pins, so scores may drift slightly
  with future LightGBM / scikit-learn releases.
- Further risks of optimism are listed in [LEAKAGE.md](LEAKAGE.md).
